# Multi-Episode Restructure: Shared Library + Episode Folders

## Context

Episode 1 (childhood diarrhea) is complete. Upcoming episodes (potentially 50+) will reuse the same characters (doctor, mother, child), objects, and sometimes rooms, while adding new rooms, characters, and props. Today everything episode-specific lives at the repo root (`scenario.json`, `timing.json`, `subtitles.srt`, `audio/`, `render/`) and ep01 choreography is hardcoded in `src/js/timeline.js` (the L01–L09 plan table, walk timings), `tools/compute-timing.js` (SETTLE_AFTER_L01), and `tools/preview-shots.js` (L01–L09 shot list). We need: one shared library of characters/rooms/props + one folder per episode, so a new episode = new data files, not code edits.

## New structure

```
F:\Animation\
├── library/                          ← shared across ALL episodes (renamed from assets/)
│   ├── characters/  doctor.json, mother.json, child.json (+future: nurse, …)
│   ├── rooms/       visit-room.json, FLOORPLAN.md (+future rooms)
│   └── props/       props.json (+future prop packs)
├── episodes/
│   └── ep01-childhood-diarrhea/
│       ├── scenario.json             ← moved from root (gains "staging" section, see below)
│       ├── timing.json               ← generated, moved
│       ├── subtitles.srt             ← generated, moved
│       ├── audio/                    ← L01..L09.mp3 moved
│       └── render/                   ← final.mp4, hooks, frames, preview moved
├── src/                              ← engine, episode-agnostic
├── tools/                            ← pipeline, parameterized by episode id
├── config/voices.json                ← stays (shared per-speaker voices)
└── README.md                         ← updated: file map + "how to add episode 2" recipe
```

Episode selection: `--ep <id>` CLI flag or `EP` env var on all tools (default `ep01-childhood-diarrhea`); browser preview uses `?ep=ep01-childhood-diarrhea` URL param. `scenario.json` already declares `id`, `location`, `characters` — these become the wiring: which room JSON, which character JSONs, which prop packs to load.

## Changes by file

### Data moves (`git mv` to preserve history)
- `assets/` → `library/` (subfolders keep names).
- Root `scenario.json`, `timing.json`, `subtitles.srt`, `audio/*`, `render/*` → `episodes/ep01-childhood-diarrhea/`.

### scenario.json (ep01) — add staging data now hardcoded in JS
- New `"staging"` section holding what's in `src/js/timeline.js:60-105` and the end-card offsets (timeline.js:167-170): the `plan` array (`{id, shot, foods/warning/heart/nod}`), walk-in choreography (per-character start/duration, dest marks), end-card lead-in. Engine stays generic; flags → effect handlers.
- Add `"settleAfter": 1.9` on line L01 to replace the `SETTLE_AFTER_L01` hack (tools/compute-timing.js:13,80).
- Add `"props": ["explainer-props"]` (prop-pack list; matches current `assets/props/props.json` id).
- Character JSONs gain `"label": "دکتر"` (Persian subtitle label) and `"subtitleColor"` (moves the hardcoded CSS speaker colors, src/css/style.css:59-61, into data so new characters work without CSS edits).

### Engine (src/)
- **main.js** — parse `?ep=`; load `episodes/<ep>/scenario.json`; load room via `scenario.location`, characters via `scenario.characters` array (replaces hardcoded trio at main.js:63-70,128), prop packs via `scenario.props`; timing path `episodes/<ep>/timing.json`; speaker label/color from character defs (replaces `SPEAKER_KEYS` map, main.js:164).
- **timeline.js** — `buildTimeline()` reads `scenario.staging` instead of the hardcoded plan/walk constants; helpers (`setShot`, `rigWalk`, `talkWindow`, `subtitle`, `audioCue`, `pop`) unchanged; effect flags (foods/warning/heart/nod) stay as generic handlers.
- **blocking.js** — unchanged behavior; add optional `roomDef.shots` override merged over the derived shot table, so a future room can define custom cameras in its JSON.
- **world.js, voxel.js, characters.js, audio.js** — already generic; only audio.js path `../audio/` → `../episodes/<ep>/audio/` (passed in, not hardcoded).
- **index.html** — remove hardcoded ep01 title/overlay text (runtime overwrites it anyway).

### Tools (all resolve paths via a tiny shared helper `tools/ep.js`: `--ep`/`EP` → `episodes/<ep>/`)
- **render.js** — output `episodes/<ep>/render/frames`; pass `&ep=` in URL.
- **assemble.js, compute-timing.js, build-subtitles.js, generate-voice-elevenlabs.js, generate-voice-edge.py, make-hook-cards.js** — episode-dir paths; compute-timing uses `settleAfter`.
- **make-hook-cards.js / make-hook-intro-card.py** — background frame from `hooks.intro.frameAt × total frames` instead of hardcoded `f_00200.png`.
- **preview-shots.js** — shot-change list derived from `scenario.staging.plan` instead of hardcoded L01–L09.
- **serve.js, Run.bat** — Run.bat opens `?ep=ep01-childhood-diarrhea`.

### README.md — rewrite file map; add "Adding episode N" recipe (new scenario.json + staging; reuse library items; only touch library when adding a new character/room/prop) and "Extending the library" notes.

## Verification (ep01 must come out identical)

1. `node tools/compute-timing.js && node tools/build-subtitles.js --ep ep01-childhood-diarrhea` → diff generated `timing.json`/`subtitles.srt` against the moved originals — must be identical (same audio).
2. `node tools/preview-shots.js` → compare `episodes/ep01.../render/preview/*.png` against the previous preview set (same framing).
3. `node tools/serve.js` → open `http://127.0.0.1:8090/src/index.html?ep=ep01-childhood-diarrhea`, press پخش — full playback check (walk-in, food pops, warning, heart, end card).
4. Spot re-render a short frame range via `tools/render.js` and compare against the shipped `render/frames` for those indices.
5. Commit the restructure as one commit.

Then the repo is ready: you send scenario 2 (+ room guide), and we create `episodes/ep02-<slug>/scenario.json` with its staging — reusing `library/` as-is.
